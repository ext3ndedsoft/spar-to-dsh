# spar

Техническая документация плагина. Пользовательский обзор — в [корневом
README](../../README.md).

## Состав

| Файл | Что делает |
|---|---|
| `index.js` | тул `spar`: действия, маршруты, ход, приговор, настройки |
| `client.js` | карточка хода и панель; регистрируется как клиентский плагин |
| `tools.js` | `read`, `grep`, `glob`, `git` в клетке каталога спора |
| `live.js` | реестр текущих ходов, который читает карточка |
| `settings.js` | `~/.dsh/spar/settings.json`, каталог моделей, HTTP-обработчики |
| `test.mjs` | офлайн-набор, без сети |
| `smoke-client.cjs` | рендер карточки и панели без браузера |

## Модели не заданы намеренно

Плагин не привозит ни одного имени провайдера. Каталог моделей у каждой
установки свой, а мост подписочного Gemini есть не у всех. Пока модель не
выбрана, `open` и `verdict` честно падают с указанием, где её взять: в панели
`◈` или в конфиге профиля.

```yaml
- insert:
    - id: spar
      name: "./plugins/spar/index.js"
      config:
        defaultOpponent: "<provider>/<model>"   # из каталога вашего харнесса
        judge: "<provider>/<model>"
        challenger: "<provider>/<model>"
```

Алиасы — сахар, их объявляет профиль, а не плагин:

```yaml
        opponents:
          gem: { provider: "antigravity", model: "gemini-3.8-flash" }
          ds:  { provider: "zexkora", model: "deepseek-v4.1-flash-1017" }
```

## Чтение проекта

`read` отдаёт срез (по умолчанию 200 строк) и всегда пишет, что именно покрыл:
`index.js · lines 1-200 of 1511`. Для аргумента о файле целиком есть
`whole: true` — он читает столько, сколько влезает в потолок 256 КБ.

В следе хода это видно как `read index.js (1-200/1511)`: не только что открыто,
но и сколько прочитано. След уходит в карточку, в транскрипт и судье.

Бюджет хода — 512 КБ текста. Когда он кончается, модель получает об этом
строку и обязана назвать, что не открыла; молчаливой стены больше нет.

## Действия

| Действие | Обязательное | Что делает |
|---|---|---|
| `open` | `topic` | начинает спор: оппонент отвечает первым |
| `say` | `id`, `message` | ваш ход в существующем споре |
| `result` | `id` | отдаёт последний ход; ждёт, если он ещё пишется |
| `status` | `id` | состояние: ходы, маршруты, идёт ли ход сейчас |
| `show` | `id` | транскрипт целиком, включая приговоры |
| `verdict` | `id` | приговор в чистом контексте |
| `duel` | `topic` | две модели спорят между собой, вызывающий смотрит |
| `close` | `id` | помечает спор закрытым, файл остаётся |
| `models` | — | каталог `provider/model` этого харнесса |

Общие параметры: `cwd` (что читают участники), `opponent`/`sides`, `judge`,
`rounds`, `tools`, `async`, `waitMs`.

### Асинхронность

`open`, `say` и `verdict` по умолчанию возвращаются сразу (`· started`), работа
идёт в фоне. `result` ждёт до 120 с (до 300 по `waitMs`) и отдаёт `result
pending`, если ход не успел: незавершённый ход нельзя выдавать за прочитанный.

## Заголовки, которые разбирает карточка

```text
[spar d14 · r3 · antigravity/gemini-3.8-flash · 97.5s]
[spar d14 · verdict · zexkora/deepseek-v4.1-flash-1017 · 37.8s]
[spar d14 · result r3 · antigravity/gemini-3.8-flash · 97.5s]
[spar d14 · result pending · antigravity/gemini-3.8-flash · 120s]
[spar d14 · started]
```

`result` — квитанция: текст уже показан в карточке хода, поэтому карточка
сворачивается в строку «ответ получен · N знаков».

## Файлы состояния

```text
~/.dsh/spar/dN.json        транскрипт: тема, ходы, прочитанное, приговор
~/.dsh/spar/settings.json  выбор из панели; пустое значение = дефолт профиля
```

Транскрипт хранит промпты, ответы и пути — это приватные данные.

## Маршруты

| Маршрут | Метод | Назначение |
|---|---|---|
| `/spar-live?call=<id>` | GET | состояние хода для карточки; без `call` — самый свежий |
| `/spar-settings` | GET/POST | чтение и запись настроек |
| `/spar-models` | GET | каталог моделей харнесса |

Отвечают без авторизации на loopback — см. [SECURITY.md](../../SECURITY.md).

## Ловушки, на которые уже наступили

- Клиентский плагин обязан объявить `inject: ["slots"]`, иначе падает весь
  плагин, а не только интерфейс.
- `jsx(type, props, children)` с третьим аргументом теряет детей: дети только
  внутри `props`, ключ тоже.
- Подготовленный вызов модели диспатчится один раз — `prepareCall` внутри цикла,
  а не снаружи.
- `arguments` вызова инструмента приходят и строкой, и объектом: разбор обязан
  принимать оба вида, иначе каждый вызов падает с «path is required».
- Судья должен читать каталог спора: `cwd` сессии и `cwd` спора — разные вещи.
