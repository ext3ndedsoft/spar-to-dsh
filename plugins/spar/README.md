# spar

Вторая модель на другой стороне стола. Не «чат с помощником»: оппонент
обязан ломать тезис, признавать только доказанное и называть тест, который
закрыл бы спор. Диалог живёт на диске, поэтому переживает компакцию и
перезапуск.

```
open  → id + атака оппонента       say     → мой ход, в ответ возражение
duel  → две модели спорят без меня verdict → третий, незаинтересованный судья
show  → весь транскрипт            list    → споры, алиасы, живые маршруты
close → закрыть (файл остаётся)
```

## Зачем два файла

`index.js` — хост: регистрирует инструмент `spar` и ходит в модели через
`ctx.llm.stream`, то есть через собственный реестр провайдеров харнесса.
Поэтому мост Gemini (`antigravity`), `zexkora` и `basisweb` работают без
единой строчки про их транспорт, ключи и квоты.

`client.js` — браузер: регистрирует вид для `tool.call.toolview` с ключом
`spar` и рисует ответ как реплику — цветная полоса в акценте семейства
модели, имя, раунд, длительность, код в блоках. Служебные результаты
(`list`, `show`, `close`) не притворяются голосом: у них тихая карточка
`служебное`.

Клиентская половина объявлена в `package.json` (`dsh.client.platform: web`,
`exports["./client"]`) и собирается силами харнесса — сборки нет, только
базовые модули `react` и `react/jsx-runtime`.

**Ловушка, на которой это ломается:** возвращаемый плагин обязан объявить
`inject: ["slots"]`. Песочница динамических пакетов не пускает к сервису,
которого нет в объявлении, и роняет загрузку всей половины — в браузере это
выглядит как «не удалось загрузить плагин», без имён файлов и строк.
Правильная форма: `return { name, inject: ["slots"], apply }`.

## Маршруты

Алиасы живут в конфиге строки плагина (`opponents`), значение — либо алиас,
либо явный `provider/model`:

| алиас | маршрут |
|---|---|
| `gemini` | `antigravity/gemini-3.8-flash` |
| `gemini-tiered` | `antigravity/gemini-3.8-flash-tiered` |
| `claude-ag` | `antigravity/claude-opus-4-6-thinking` |
| `sonnet-ag` | `antigravity/claude-sonnet-4-6` |
| `kimi` | `zexkora/kimi-k3` |
| `deepseek` | `zexkora/deepseek-v4.1-flash-1017` |

Судья по умолчанию — `deepseek`, то есть та же модель, что ведёт спор, на том
же шлюзе. Это выбор по замеру, не по вкусу: Gemini отвечает за 12 с, claude на
мосту — за 25 с, а `glm-5.3-flash` и `kimi-k3` на этом шлюзе думают дольше
четырёх минут и срываются по таймауту. Пока судья не отвечает вовремя, он не
судья.

Непредвзятость двойника держится не на весах, а на контексте:

- вызов идёт в чистом контексте — модель не помнит, что спорила, и не видит
  собственных ходов как «своих»;
- стороны обезличены (`SIDE A` / `SIDE B`), порядок меняется от вердикта к
  вердикту устойчивым хешем, так что позиционной привычки не появляется;
- в системном промпте прямо сказано: если какая-то реплика кажется тебе своей,
  это повод копнуть строже, а не аргумент;
- сначала обязательный steelman стороны, которую судья склонен отклонить, и
  только потом разделы «выжило / опровергнуто / долг / вердикт».

Кому именно соответствует A и B, сообщается после вердикта, отдельной строкой.
Судья, совпадающий со стороной спора, запрещён: `verdict` откажется.

## Режимы

`strike` (по умолчанию) — оппонент атакует тезис. `steelman` — строит
сильнейшую версию позиции, против которой идёт спор. `cross` — отвечает по
существу, но помечает невысказанные допущения. `intensity`: `civil` /
`sharp` / `brutal` (brutal называет fallacy по имени, но не переходит на
личности и без мата в адрес оппонента).

## Бюджет

Транскрипт перечитывается целиком каждый раунд: провайдеры остаются
stateless, а спор можно менять модель по ходу. Поэтому старые ходы
вытесняются по `maxTranscriptChars`, первая пара и последние ходы
сохраняются. Ответы режутся по `maxReplyTokens` (по умолчанию 8192), вердикт —
по `judgeTokens` (16384): на маршрутах, которые думают перед ответом, шлюз
считает размышления и текст общим лимитом, и на маленьком бюджете приходит
финиш без единого слова прозы. Время — по `timeoutMs`, для вердикта не меньше
240 с. Одновременно по одному спору идёт ровно один запрос.

## Чтение проекта

Оппонент не верит пересказу — он читает сам. В каждом ходе модель может
вызвать `read` / `grep` / `glob` / `git`, плагин выполняет вызов у себя
(`tools.js`) и возвращает результат обратно в тот же диалог. Это настоящий
tool loop, а не вклеенный промпт: файл, который модель открыла, она видит
целиком, и в карточке видно, что именно она читала.

Корень спора — `cwd` спора (параметр или конфиг, иначе cwd профиля). Всё, что
за корнем, вырезается (`path escapes the debate root`); секреты — `.env`,
ключи, `id_rsa`, `.ssh`, `.aws`, `.npmrc`, `*.pem`, `secrets*` — режутся
политикой. На ход даётся `maxToolRounds` вызовов и 24 КБ прочитанного; после
этого тулы отключаются и модель обязана ответить прозой. `git` только читает:
`status`, `diff`, `log`, `ls-files`.

Дерево видно целиком: `glob` показывает и папки (с `/` на конце), `dir/**`
значит «всё внутри dir», а `read` от папки печатает её содержимое. Без этого
промежуточная папка выглядит пустой, и модель уверенно заявляет, что кода нет.

## Живая карточка и async

Результат тула существует только целиком, поэтому пока модель пишет, хост
держит ход в памяти и отдаёт его по `GET /spar-live?call=<callId>`. Карточка
опрашивает этот маршрут и рисует текст по мере роста — видно, как оппонент
думает, и видно список того, что он уже прочитал (`› read docs/UEFI_TIER.md`).

`async` включён по умолчанию у `open` / `say` / `verdict`: тул сразу отвечает
`started`, работа идёт в фоне, карточка продолжает наполняться. Готовый ход
забирается через `action:"result", id:"dN"` — то есть ход тула не блокирует
агента. `async:false` ждёт ответа (нужно, когда спорить не с чем, пока не
прочитал возражение). `duel` всегда ждёт: там смысл именно в полном обмене.

`result` ждёт. Если ход ещё пишется, он висит до 120 с (до 300 по `waitMs`),
а не подсовывает прошлый ход: непрочитанная реплика — не реплика. Отвечать,
не забрав её, нельзя; а если она кажется бредом, это решает судья, а не
вызывающий. `wait:false` отдаёт `result pending` и прямо говорит, что
заканчивать ход нельзя.

Карточка `result` — квитанция, а не второй экземпляр ответа: текст уже виден в
карточке хода, поэтому здесь только строка «ответ получен · N знаков» и
кнопка «показать». Для ещё не готового хода — «ответ ещё не готов».

## Язык

`language: "ru"` (по умолчанию) или `"en"`. Влияет на обе стороны, на судью и
на то, как в транскрипте называется вызывающий агент (`вызывающий агент` /
`calling agent`) — то есть на всё, что читает человек. Служебная шапка
`[spar d3 · r2 · provider/model · 12.4s]` намеренно остаётся английской: по
ней клиентская половина разбирает результат, и переводить её — значит ломать
отрисовку. Код, пути и цитаты в ответах не переводятся.

## Конфиг

Все поля необязательны, значения по умолчанию — в `DEFAULTS` в `index.js`.
Значимые: `defaultOpponent`, `challenger` (вторая сторона дуэли), `judge`,
`language`, `maxReplyTokens`, `judgeTokens`, `temperature`, `timeoutMs`, `dir`
(по умолчанию `~/.dsh/spar`), `leftLabel` (как меня зовут в транскрипте; по
умолчанию — по языку), `tools` (по умолчанию `true`), `cwd` (корень, который
читают спорящие), `maxToolRounds` (по умолчанию 3).

## Файлы для спора

`files: ["src/x.ts"]` — до 4 файлов по 60 КБ, общий бюджет
`maxAttachChars`. Текст уходит оппоненту как приложенный контекст, а не как
его собственный аргумент; нечитаемый путь не ломает ход, а помечается в
транскрипте.

## То, что важно знать

- Клиентская половина появляется в открытой вкладке после перезапуска
  веб-приложения: метаданные пакета кешируются на строку загрузчика до
  рестарта. Хостовая половина перезагружается на лету.
- Проект, где споры не нужны или где модель отказывается, отключается
  строкой плагина в менеджере плагинов — это нормальная форма «здесь не
  надо» для харнесса.
- Отказ провайдера (лимит, пустой ответ) приходит наверх как ошибка со
  своим кодом; на карточке это красная реплика «не ответила», а не тихий
  пустой ход.
- `prepareCall` готовит вызов ровно на один `stream()`: в цикле с тулами его
  надо звать заново на каждый раунд, иначе прилетает `a prepared LLM call can
  only be dispatched once`. Добавлять `temperature` в `stream()` позже тоже
  нельзя — только в `prepareCall`.
- `live` пишется по `exec.rootCallId`, поэтому карточке не нужно знать id
  спора: каждый ход публикуется в свой канал.
